# Android plugin (Kotlin)

Location: `src-tauri/gen/android/app/src/main/java/dev/mogabridge/app/moga/`. Everything Android-specific lives here. The package equals the app identifier (`dev.mogabridge.app`) plus `.moga`; Rust registers the plugin by that name (`constants/android.rs`).

> `gen/android` is generated by `tauri android init`, but this folder, the manifest additions and `res/raw/helper_script.sh` are **project source**: keep them under version control and preserve them if the Android project is ever regenerated ([building-and-signing.md](../development/building-and-signing.md#regenerating-the-android-project)).

## Classes

One class per responsibility. `MogaAndroidPlugin` is only the command layer and the wiring.

| Class | Responsibility |
|---|---|
| `MogaAndroidPlugin` | Tauri `@Command` handlers, permission checks, lifecycle hooks (`onPause`, `onResume`, `onDestroy`), connection orchestration (`openConnection`/`closeConnection`). A static `instance` serves the notification's *Disconnect* action. |
| `MogaPreferences` | The single owner of `SharedPreferences`: output mode, stick layout, key mapping with defaults and validation. Also the `OutputModes` and `StickLayouts` constants. |
| `MogaDevices` | Name filter (`isMogaName`, `isMogaDevice`), the `DeviceInfo` map for the UI, and small Bluetooth helpers (`bluetoothAdapter()`, `Intent.bluetoothDevice()`, `registerBluetoothReceiver`). |
| `DeviceDiscovery` | Classic inquiry with a temporary receiver; publishes `moga-discovered-devices`. |
| `DeviceBonding` | `createBond()` and waiting for the result, cancellable. |
| `RfcommSockets` | The five socket creation strategies (some via reflection). |
| `RfcommConnector` | Tries the strategies in rounds with delays; cancellable. |
| `ControllerLink` | The open link: reader thread, bounded queue of chunks, `take()`, `write()`, `close()`. |
| `UinputBridge` | The virtual gamepad client (details in [virtual-gamepad.md](virtual-gamepad.md)). |
| `HelperFiles` | Generates `helper.token` and `helper.sh` in the app's external private directory and builds the start command. |
| `MogaInputMethodService` | Keyboard fallback: key events from the controller's digital directions and buttons. |
| `MogaConnectionService` | Foreground service + persistent notification while connecting/connected. |
| `MainActivity` | Generated Tauri activity (untouched). |

## Commands

Names must match the strings in `src-tauri/src/drivers/android.rs`.

| Command | Notes |
|---|---|
| `requestBluetoothPermission` / `bluetoothPermissionResult` | Requests the set for the running Android version (adds notifications on 13+). Only the Bluetooth permissions must be granted. |
| `scan`, `scanUnpairedDevices`, `stopDeviceScan` | Paired MOGA devices; start/stop the inquiry. |
| `connect`, `disconnect` | `connect` shows the notification first (foreground services may only start while visible) and then runs `openConnection` on its own thread. |
| `read`, `write` | The byte stream for the Rust session: `read` blocks on a dedicated executor until a chunk (or the end marker) arrives. |
| `dispatchState` | Hot path: forwards a decoded state to the virtual gamepad (default) or the IME. |
| `getOutputSettings` | Mode, stick layout, helper reachability/command/error, isolation flag. Runs on `moga-io`. |
| `setOutputMode`, `setStickLayout`, `setInputIsolated` | Settings; the bridge is re-synchronised. |
| `getMapping`, `setMapping` | Keyboard-mode key mapping. |
| `openBatterySettings`, `openImeSettings` | Open system screens. |

## Connection orchestration

`openConnection(args)`: permission check → `closeConnection()` (reset) → pair if needed → `RfcommConnector.connect` → attach under `connectionLock` (re-checking cancellation) → show the *connected* notification → `syncBridge()` → start the reader with an `onEnded` callback that releases the bridge and the notification. `closeConnection()` bumps a generation counter and cancels bonding, the connector and the link under the same lock; it is idempotent.

`syncBridge()` keeps `UinputBridge.setActive(...)` equal to *(a controller is connected) and (output mode is gamepad)*. `applyIsolation()` keeps the bridge suspended exactly while test isolation is on.

## Lifecycle rules

- `onPause`: isolation is switched off (so the controller reaches whatever app is in front). `onResume`: the bridge is nudged to re-check its connection. `onDestroy`: discovery stopped, connection closed, notification stopped, bridge shut down, executors shut down, `instance` cleared.
- The connection survives the app going to the background because the foreground service keeps the process important.

## Preferences

Two files: `moga-output` (`mode`, `stickLayout`) and `moga-key-mapping` (one int per control). `saveKeyMapping` clears and rewrites the mapping and rejects codes outside `0..288`. The default mapping is a common emulator keyboard layout (Z X A S, Q W, Space, V, arrows, I J K L). Control names must match `KeyMapping` in `schemas/settings.rs` and `src/lib/keys.js`.

## Notification (`MogaConnectionService`)

A `connectedDevice` foreground service with channel `moga_connection` (low importance), an ongoing notification ("Conectando mando…" → "Mando conectado"), a content intent that opens the app and a *Desconectar* action that calls `MogaAndroidPlugin.requestDisconnect()`. If Android refuses to start the service the bridge keeps working without the notification. The small icon is the legacy controller glyph (`res/drawable-*/ic_stat_moga.png`).

## Keyboard fallback (`MogaInputMethodService`)

An `InputMethodService` the user must enable and select. It sends one key tap (`sendDownUpKeyEvents`) per newly pressed mapped control from the digital stick directions and buttons. Android delivers those only to the **focused text field**, so this cannot drive games or emulators and has no analog input; it exists as a fallback and for the original app's "virtual keyboard" parity. Key codes are cached and refreshed by `mappingChanged()`.

## Manifest additions

Permissions (Bluetooth, notifications, foreground service types), the `MogaConnectionService` (`foregroundServiceType="connectedDevice"`) and the IME service with its metadata. Resources: `res/raw/helper_script.sh` (helper template), `res/drawable-*/ic_stat_moga.png`, the app icons (generated from the legacy launcher by `pnpm tauri icon`), the strings `app_name` and `moga_ime_*`.

## Threading and resources

See the thread table in [overview.md](overview.md#threads). Every receiver registered is unregistered on stop/destroy; every thread started either ends with its socket or is a daemon; executors are shut down in `onDestroy`. If you add a thread or a receiver, add its teardown in the same change.
